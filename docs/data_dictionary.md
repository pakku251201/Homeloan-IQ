# Data dictionary

All records generated by `make_data.py` are synthetic and reproducible (`random.seed(7)`). The generator creates 600 applicants.

| CSV / BigQuery table | Grain | Key fields |
|---|---|---|
| `customers` | One row per customer | `customer_id`, `name`, `employer_type`, `income`, `existing_emi`, `kyc_status` |
| `accounts` | One row per customer | `customer_id`, `avg_balance` |
| `repayments` | One row per customer-month where an existing EMI exists | `customer_id`, `month`, `bounced` |
| `bureau` | Mock bureau response when available | `customer_id`, `cibil` |
| `cersai` | One row per application | `application_id`, `charge` |
| `applications` | One row per loan application | `application_id`, `customer_id`, `amount`, `property_value`, `years`, `doc_issue` |
| `decision_log` | One row per officer action | `application_id`, `officer_decision`, `logged_at` |
| `applicant_view` | One joined row per application (subject to source joins) | `id`, applicant fields, bureau, collateral, repayments and document flag |

`cibil`, `charge`, repayment bounces and document issues are mock/synthetic, not live external-service results. The loader uses `WRITE_TRUNCATE` for the six generated source tables, so rerunning it replaces their rows. Officer decisions are kept in the separate decision log.
